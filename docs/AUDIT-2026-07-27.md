# Hermes Mission Control — System Audit
**Date:** 2026-07-27 · **Auditor:** Claude (read-only — no destructive changes made)

## TL;DR
The current system is a solid **personal agent cockpit** but it is not an agency OS, and the current stack can't become one. It's a 2,964-line single-file Python stdlib server + an 84KB single-file HTML app with no version control, no auth, no tests to speak of, and ~80% of the Agency OS scope (clients, projects, approvals, SEO workspace, reporting) simply doesn't exist yet. The agent bridge and Hermes telemetry are the genuinely valuable parts — keep them. Everything else should be rebuilt on a real framework.

**One live bug found:** the watchdog is stuck in an infinite repair loop (see Broken, item 1).

| Layer | Reality |

### API surface (~25 endpoints)
Board CRUD, missions (update/fork/events), workflows + runs, bridge (send/history/favorite/upload), content read/save, flight recorder, snapshot, SSE `/events`, uploads.

## 2. What currently works (keep this)

1. **Agent bridge** — send prompts to any of 10 agents (or `@all`) through the Hermes gateway with SSE streaming, history, favorites, and file attachments. This is the core asset.
2. **Hermes telemetry** — read-only (URI mode + `query_only=1`) reads of runtime DBs: per-agent activity, sessions, token totals, cron jobs, VPS health. Good defensive engineering.
3. **Missions cockpit** — objective/phase/decisions/blockers/confidence + event log + fork. A reasonable seed for "projects."
4. **Workflows store** — workflow + run tables exist (thin, but a seed for orchestration).
5. **Careful details worth preserving** — BOM-tolerant `.env` parsing, upload path-traversal guards (`relative_to` checks), client-disconnect errno handling, startup JS duplicate-declaration check.

## 3. What is broken or incomplete

1. **Watchdog crash-repair loop (live, right now).** `watch-mission-control.ps1` runs a strict health check every ~30s; `Test-ProfilesHealthy` fails every cycle, triggering a full launcher "repair" that succeeds on mission+API, then fails profiles again. Result: endless process churn, a 296KB log, and repair spam since at least 11:43 today. The repair function never checks profiles after repairing, so it declares "Repair successful" while the actual failing condition persists.
2. **SEO view is cosmetic.** The SEO/AEO/GEO score rings read from `localStorage['seo-data']` — there is no backend, no data source, no persistence. "⚡ Live audit" just composes a chat message to an agent. This violates your own "do not fabricate SEO data" rule.
3. **Stale hardcoded port.** `index.html` still references `http://127.0.0.1:4173` (`/api/seo-data`, `/api/bridge/history`) while the server runs on 51764 — those fetches are dead code or silent failures.
4. **Browser rendering issue.** The live page hung a fresh browser tab during audit (screenshot timed out twice) — likely the SSE `/events` stream or polling loop blocking first paint. Worth confirming, since it matches the watchdog's "unhealthy" signal.
5. **Jarvis voice view** — experimental, tied to Web Speech APIs, state unclear.
6. **Seeded fake tasks** in `board.db` presented as real work items.
7. Only 2 test files (`test_bridge_attachments.py`, `test_mission_memory.py`). No CI. No lint. No type checking enforced.

## 4. Technical debt

- **No git.** One bad edit loses everything. The 9 manual backup files (`index.html.backup-*`, `server.py.bak-*`) are doing git's job badly.
- **Root directory litter:** 17 `_inline_*.js` check artifacts, ~20 log files, lighthouse JSON, `.venv`, `__pycache__`, backups — all in root.
- **Duplicate definitions in `server.py`:** `MAX_UPLOAD_BYTES` defined twice with different values (8MB then 12MB — the second silently wins), `ensure_upload_root`/`sanitize_upload_name`/`save_uploaded_file` defined twice. Classic single-file-grew-too-big symptoms.
- **Two overlapping mission schemas** (`missions.db` and `mission_memory.db` both define `missions` + `mission_events`).
- **Google Fonts CDN dependency** — UI degrades offline.
- **Monolith risk:** every feature added to the two megafiles increases regression surface; the `_inline_*_check.js` graveyard is evidence this already bit you repeatedly.

## 5. Security

| Issue | Severity | Note |
|---|---|---|
| No authentication on any endpoint | High (contextual) | Localhost-only binding mitigates, but any local process or malicious web page (DNS rebinding / CSRF-style POSTs) can hit `POST /api/bridge/send` and spend your gateway tokens, read session history, or wipe tasks/workflows |
| No CSRF protection, no origin checks | High | Same vector as above — a web page you visit can POST to `127.0.0.1:51764` |
| No rate limiting | Medium | Bridge send → gateway spend is unbounded |
| No audit logging | Medium | No record of who/what triggered agent actions |
| Secrets handling | OK | `API_SERVER_KEY` loaded from Hermes `.env`, never hardcoded; keep this pattern |
| Upload handling | OK | Path traversal guarded via `relative_to`; size caps exist |
| Subprocess use | OK | Only a notification script and `node --check` syntax validation |

## 8. Recommended architecture

The stdlib-server + single-HTML approach was right for a cockpit; it cannot carry clients, RBAC, approvals, an SEO data model, and reporting. Recommendation:

- **Frontend:** React + Vite + TypeScript + Tailwind + shadcn/ui. Component reuse is non-negotiable at this scope.
- **Backend:** FastAPI (Python — continuity with your existing code and skills). Port the bridge, telemetry readers, and upload logic over largely intact. Pydantic models give you validation for free.
- **DB:** Single SQLite database with migrations (Alembic), designed multi-tenant (client_id on everything) so Postgres is a config swap later.
- **Agent layer:** Keep the Hermes gateway exactly as-is; add an orchestration table layer (agent registry, runs, states, approvals, cost log) on top.
- **Integrations:** Adapter pattern — GSC, GA4, Ahrefs/DataForSEO, GitHub, Vercel, Stripe each behind an interface with `estimated | imported | verified` data provenance flags on every metric. No key → feature shows "not connected," never fake numbers.
- **First act of implementation:** `git init` + .gitignore, before anything else.
